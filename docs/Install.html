Programmer Workflow · Install

安装与验证

同一个 Skill 可以装到多个 Agent/编辑器；它们的数据目录彼此独立。安装完成后的第一件事是用对应宿主的 --host 运行 doctor。

当前为 v0.1.1 测试版：DSH 支持根包 GitHub 安装；Kimi 仍用官方 /plugins install。真实宿主的迁移尚未由本插件验证，详见 Migration.html。

先选宿主

宿主插件数据根（默认）安装位置
DeepSeek Harness<DSH_HOME>/programmer-workflow~/.dsh/skills / 项目 .agents/skills
Kimi Code<KIMI_HOME>/programmer-workflow~/.kimi-code/skills 或 Kimi 插件

不要假设 Kimi/CodeBuddy 会读取 DSH 的 ~/.dsh/programmer-workflow。非 DSH 宿主没有该兜底。旧的共享数据只能用“一次性导入”进入对应宿主，不会自动同步。

DSH

1. 默认方式：根包安装

dsh plugin --profile web add github:xukirito/programmer-workflow

在仓库根目录也可执行 dsh plugin --profile web add .。根 package.json 声明 dsh.bundle.patch、dsh.client 和 exports，包内包含 Skill、命令和 Host/Client；首次加载会把内置 Skill 复制到 <DSH_HOME>/skills/programmer-workflow（已存在则保留）。

如果此前装过旧的 @local/programmer-workflow 本地组合包，先卸载旧包，避免同一个 loader entry 被两个包声明。

2. 可选：受管启动块

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Targets dsh -HostId dsh -Bootstrap

需要把 boot 块写入 AGENTS.md 或做离线安装时使用；项目级用 -Targets project -HostId dsh -Bootstrap。

3. 验证

python "%USERPROFILE%\.dsh\skills\programmer-workflow\scripts\companion.py" doctor --host dsh --workspace .
python "%USERPROFILE%\.dsh\skills\programmer-workflow\scripts\companion.py" env probe --host dsh --workspace .

设置页会分别显示应用数据、插件数据、工作区数据和两个迁移阶段；左下角账号栏上方会显示余额（可在设置中关闭），/screenshot 或 /截图 会捕获并复制 PNG，再由大模型读取图中文字，不使用本机 OCR。

Kimi Code

插件安装（推荐）

在 Kimi Code 中执行 /plugins install，指向本仓库根目录；插件会加载 Skill、系统提示和命令。

用户级 / 项目级安装

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Targets kimi -HostId kimi -Bootstrap
python "%USERPROFILE%\.kimi-code\skills\programmer-workflow\scripts\companion.py" doctor --host kimi --workspace .

打开本地设置页

插件启用后，官方 manifest 的 hooks.SessionStart 会在本机幂等启动 127.0.0.1:8765；在“我的插件”里打开该插件的详情，点击“主页”即可通过 /quick 跳到带 token 的设置页，不需要输入命令或消耗模型额度。Kimi 1.3.2 的“更多操作”菜单目前只有卸载，因此快捷入口使用官方支持的 homepage 字段；如果当前版本没有渲染主页链接，直接在浏览器打开 http://127.0.0.1:8765/quick?host=kimi。

python "<skill>/scripts/companion.py" settings --host kimi --workspace . --open
在 Kimi 中也可以直接执行 /programmer-workflow:settings 作为回退。Agent 会从当前加载的 Skill 定位 CLI；通过 /plugins install 安装时运行的是 plugins/managed 下的副本，不要写死 ~/.kimi-code/skills。页面只监听 127.0.0.1，URL 以 #token=... 携带令牌；它只准备迁移/回滚脚本，不执行迁移。
Kimi 插件数据根是 ~/.kimi-code/programmer-workflow，不是 DSH 的 .dsh。Kimi 运行数据迁移要求 kimiMigrationTools 目录同时含迁移与回滚脚本，且适配器读取 KIMI_MIG_SRC；否则显示“未配置/不可用”，不会成“已验证”。

CodeBuddy

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Targets codebuddy -ProjectRoot <项目根> -Bootstrap

会写入项目 .codebuddy/skills/programmer-workflow 和 CODEBUDDY.md。项目级 Skill 只解决项目工作区；用户级插件数据在 ~/.codebuddy/programmer-workflow，不会写进 .dsh。

CodeBuddy 的插件数据在注册表里是支持的，但第一阶段需要该宿主的 Skill CLI（~/.codebuddy/skills/programmer-workflow/scripts/companion.py，或用 PROGRAMMER_WORKFLOW_CLI 指定）；找不到时设置页标记不可用并禁用准备按钮。运行数据迁移未适配。

模式与迁移

  • workflowMode=plan：普通运行需批准，先生成 plan.md/plan.html，回复“执行”后用 run --yes。
  • workflowMode=full-authority：普通运行无需逐条批准，用 run --full-authority；破坏性操作仍需确认。
  • 两者 flags 同时出现会报错；该设置不改变宿主权限，也不绕过只读/沙箱。
  • 迁移第一阶段只移动当前宿主的插件数据；第二阶段才移动编辑器运行数据，且必须等第一阶段完成并校验、且适配器同时具备迁移与回滚脚本。
  • 工作区记忆在 <workspace>/.programmer-workflow，永不随全局迁移移动。

详细迁移与支持矩阵：Migration.html。
