Programmer Workflow · Migration

先插件数据，再编辑器运行数据

两个阶段有先后顺序。第一阶段只移动当前宿主的 programmer-workflow 插件数据；第二阶段才移动编辑器的会话/缓存/登录等运行数据。未适配的宿主只开放第一阶段。

第一阶段：迁移插件数据

1

目标只是当前宿主的插件目录

源：<host-home>/programmer-workflow。目标：<目标根>/<host-data-dir>/programmer-workflow。主机根分别来自 DSH_HOME、KIMI_HOME、CODEBUDDY_HOME 等；DSH_HOME 只影响 DSH。

设置页只负责预检、备份、清单和生成脚本；不会在 DSH 运行期间自动迁移。迁移后会校验 memory.json 的条目 ID、状态计数和 SHA-256，而不是只看文件数量。

python companion.py migrate-plugin status --host dsh --json
python companion.py migrate-plugin prepare --host dsh --target-root <目标根> --json
目标已有未知数据、UNC 路径、源内嵌套 Junction、或 memory.json 不可解析时，预检必须失败；不得静默合并。备份放在 <host-home>/.programmer-workflow-migration/backups，不在即将被改名的插件目录里。

第二阶段：迁移编辑器运行数据

2

只有第一阶段完成并校验后才可用

第二阶段处理会话、配置、缓存、登录等编辑器数据，有独立的目标和适配器。它不能复用 DSH/Kimi 脚本冒充通用适配器；“外部脚本存在”也不等于“已经适配”。

旧共享数据与外部 override

旧版 ~/.workflow-companion 或旧的 DSH 共享插件目录，只提供一次性导入，不会成为其他宿主的后台兜底。目标已有 memory.json 时：

  • 内容相同：跳过；
  • 内容不同：生成冲突报告，保留双方，不覆盖；
  • 不会把 proposed 提升为 active。

PROGRAMMER_WORKFLOW_GLOBAL / PROGRAMMER_WORKFLOW_HOME 指向宿主默认根之外时，状态会标记“外部路径，未由默认迁移覆盖”。请手动备份/导出，不要假装已覆盖。

回滚与嵌套 Junction

  • 回滚顺序与迁移相反：先回滚第二阶段运行数据，再回滚第一阶段插件数据。
  • 第一阶段回滚前先备份目标中“当前最新”的插件数据；与迁移时版本不同时提示存在新增/修改，并保留最新备份路径。
  • 第二阶段预检会识别第一阶段产生的嵌套 Junction；本版本只支持同一目标根下的嵌套，跨根或需要按清单重建时直接拒绝，不复制链接、也不声称已重建（部分支持）。
  • 第二阶段回滚入口是 run-stage2-rollback.cmd；第二阶段处于 prepared/completed 时，第一阶段回滚会拒绝并提示先回滚第二阶段。
  • 任一阶段失败返回非零状态并显示失败阶段，不继续下一步，也不显示整体成功。
  • 工作区记忆（<workspace>/.programmer-workflow）属于项目，不随两阶段迁移移动。

DSH / Kimi 操作提示

DSH

设置页选择 DSH，填写第一阶段目标根，点“准备第一阶段脚本”；退出 DSH 后运行生成的脚本。第二阶段使用内置的 dsh-migration-tools（目标根单独填写），且必须等第一阶段完成。自定义 DSH_HOME 时脚本使用解析后的真实源目录，不固定 %USERPROFILE%\.dsh。

Kimi Code

设置页选择 Kimi，先确认 Kimi 迁移工具路径（工具目录需同时包含 migrate-kimi-data.bat 与 rollback-kimi-data.bat，且适配器要读取 KIMI_MIG_SRC 才算可用）；准备第一阶段脚本只移动 Kimi 自己的插件目录。Kimi 运行数据迁移是第二阶段，不能宣称会带动 DSH 或共享插件记忆。

CodeBuddy / 其他宿主

项目级 Skill 只解决项目工作区；用户级插件数据在各自 <host-home>/programmer-workflow。第一阶段需要该宿主的 companion.py（或 PROGRAMMER_WORKFLOW_CLI）；找不到时设置页标记不可用并禁用准备按钮。运行数据迁移尚未适配，不提供执行入口。

本页是操作指南，不代替真实迁移；状态接口和脚本以当前代码和备份清单为准。
